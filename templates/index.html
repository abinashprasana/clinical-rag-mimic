Clinical Evidence Assistant

Evidence-grounded answers, built as an agent

Ask a clinical question and get an answer traced back to the discharge note it came from. This started as a retrieve-then-generate pipeline over MIMIC-IV-Note and grew into an agent: it routes each question to the right tool, checks its own answer against the record before showing it, and refuses rather than guesses when the note doesn't say.

How this came together

From a retrieval pipeline to something closer to an agent

This began as a plain retrieval-and-generate pipeline: embed a note, embed the question, find the closest passage, generate an answer from it. Over time it grew into something closer to an agent. A question is now routed to the right tool before it touches the record. A drug-dosage question goes to an FDA label lookup, not a guess pulled from someone's note, and every generated answer is checked against the retrieved text before it's shown, with one retry if that check fails. If neither routing nor retrieval turns up anything to ground an answer in, it says so instead of guessing.

The real numbers

What's actually running, and what it measures

Two different datasets sit behind this project, and which one you're looking at depends on where you're viewing it from.

Restricted

MIMIC-IV-Note v2.2

331,793 de-identified discharge notes from 145,914 real hospital admissions, released by PhysioNet under a credentialed Data Use Agreement. Reading one requires completing CITI training and signing that agreement, which forbids sharing access with anyone who hasn't done the same.

Public

Ten fabricated discharge notes

Written by hand for this deployment, in the same section format MIMIC-IV-Note uses. Every vital, lab result, and diagnosis is invented, with no real patient or admission behind any of it, so none of it was ever restricted to begin with.

Known boundaries

What it checks, and what it doesn't decide

What it checks

  • Every answer is compared against the passages it was retrieved from before it's shown.
  • A drug-dosage question goes to an FDA label lookup, not a guess from the note.
  • If nothing in the record supports an answer, it says so instead of guessing.
Evidence gate

What it doesn't decide

  • It doesn't determine diagnosis or treatment, since a qualified clinician reviews the record.
  • {% if public_demo %}This deployment runs on ten fabricated notes; no real patient data is used publicly.{% else %}Retrieval ranks text similarity, not clinical importance or correctness.{% endif %}
  • Evaluation uses a small, fixed question set, not a general-purpose benchmark.

Processing architecture

From question to reviewable response

Each stage exposes only what the current response contract can support. No claim-level citation mapping is inferred.

  1. 01

    Route

    Classify the request as record retrieval, FDA label lookup, clarification, or direct handling.

  2. 02

    Retrieve

    Search section-aware chunks and return the configured number of relevant passages.

  3. 03

    Generate

    {% if public_demo %}Compose an answer from the retrieved passages via the Gemini API, or quote the top passage directly if Gemini is unavailable.{% else %}Compose an answer locally from the retrieved context within model input limits.{% endif %}

  4. 04

    Check support

    Compare content words and numeric claims against the retrieved text; retry or refuse when gaps remain.

  5. 05

    Review

    Present the response with source passages, provenance identifiers, and limitations.

Known boundaries

What the system does not establish

Data and retrieval

  • {% if public_demo %}The hosted corpus contains only ten fabricated examples and is not representative clinical data.{% else %}The indexed sample does not cover the complete MIMIC-IV-Note corpus.{% endif %}
  • {% if public_demo %}If Gemini is unavailable, this deployment falls back to a simpler offline keyword-matching method with reduced retrieval quality.{% else %}Retrieval relevance ranks text similarity, not clinical importance or correctness.{% endif %}
  • Answers can omit relevant facts outside the retrieved passages.

Generation and support check

  • The generator is general-purpose and may paraphrase, omit, or misstate information.
  • The source-support check uses content-word and numeric overlap, not clinical verification.
  • Evaluation uses a small structural question set and rigid keyword matching.
