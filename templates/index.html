Clinical Evidence Assistant

Evidence-grounded answers, built as an agent

Ask a clinical question and get an answer traced to the discharge note it came from. The agent sends each question to the right tool, checks its draft against the record before you see it, and says so when the note is silent.

How this came together

From a retrieval pipeline to something closer to an agent

A discharge note can run to thousands of words, and the fact a reviewer needs usually sits in one section of it. Researchers and chart reviewers have to check every answer against that section, so each answer here arrives with the passages it used. The first version embedded the question, found the closest passage and generated from it. Routing and the support check came later. The evaluation further down measures whether each change helped.

Processing architecture

From question to reviewable response

Every question passes through the same five steps. Inside the workspace, System Overview lists what each step guarantees and where it stops.

  1. 01

    Route

    Sends the question to the note search, the FDA label lookup, or a clarifying question.

  2. 02

    Retrieve

    {% if public_demo %}Matches the question against note sections with Gemini embeddings and keeps the top five.{% else %}Searches note sections indexed with a line of context from their own note, and keeps the top five.{% endif %}

  3. 03

    Generate

    {% if public_demo %}Writes the answer from those passages through the Gemini API.{% else %}Quotes list sections word for word and writes the rest with FLAN-T5 on this machine.{% endif %}

  4. 04

    Check

    Compares the draft with the passages and retries once. If the support still isn't there, it refuses.

  5. 05

    Respond

    Shows the answer with every passage it used, ready for a person to review.

Known boundaries

What it checks, and what it doesn't decide

What it checks

  • Each answer is compared with the passages it came from before you see it.
  • Dosage questions go to the FDA drug label, never to a patient's note.
  • When nothing in the record supports an answer, it says so.
Evidence gate

What it doesn't decide

  • It doesn't diagnose or recommend treatment. A clinician reviews the record.
  • {% if public_demo %}This site runs on ten fabricated notes, so no real patient data is public.{% else %}Retrieval ranks text by similarity, which isn't the same as clinical importance.{% endif %}
  • The demo scores come from questions about ten fabricated notes, checked by one person.

Processing architecture

From question to reviewable response

Each step shows only what it can support. Answers cite passages as a whole, and no claim is mapped to a single sentence.

  1. 01

    Route

    Classify the request as record retrieval, FDA label lookup, clarification, or direct handling.

  2. 02

    Retrieve

    {% if public_demo %}Match the question against the fabricated note sections with Gemini embeddings and keep the top five passages.{% else %}Search note sections that carry a line of context from their own note, match section names on word stems, and keep the top five passages.{% endif %}

  3. 03

    Generate

    {% if public_demo %}Compose an answer from the retrieved passages through the Gemini API, or quote the top passage if Gemini is unavailable.{% else %}Split questions with several parts, quote list sections word for word, and write the rest with the local model.{% endif %}

  4. 04

    Check support

    Compare content words and numeric claims against the retrieved text; retry or refuse when gaps remain.

  5. 05

    Review

    Present the response with source passages, provenance identifiers, and limitations.

What changed since the first version

  1. Retrieval. Each note section is indexed with a line of context from its own note, and section names match on word stems. The dense_legacy row below is the index before this change.
  2. Answers. Questions with several parts are split, list sections such as discharge medications are quoted word for word, and FLAN-T5 answers the rest.
  3. Testing. Settings were tuned on one question set, then scored once on held-out questions written afterwards. The old 10 question keyword test now sits in the appendix.
  4. Model choice. Qwen2.5-1.5B scored higher than FLAN-T5 on a second held-out set, but the gap wasn't statistically significant and it runs several times slower on a laptop CPU. FLAN-T5 stays the default for now.

Known boundaries

What the system does not establish

Data and retrieval

  • {% if public_demo %}The hosted corpus contains only ten fabricated examples and is not representative clinical data.{% else %}The indexed sample does not cover the complete MIMIC-IV-Note corpus.{% endif %}
  • {% if public_demo %}If Gemini is unavailable, this deployment falls back to a simpler offline keyword-matching method with reduced retrieval quality.{% else %}Retrieval relevance ranks text similarity, not clinical importance or correctness.{% endif %}
  • Answers can omit relevant facts outside the retrieved passages.

Generation and support check

  • The generator is general-purpose and may paraphrase, omit, or misstate information.
  • The source-support check uses content-word and numeric overlap, not clinical verification.
  • Answer correctness is scored by keyword assertions on questions about ten notes, written and checked by one person.
